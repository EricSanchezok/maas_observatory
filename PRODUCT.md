# Product

## Register

product

## Users

People who use self-hosted model deployments and need to understand how quickly and reliably each responds from the MaaS Observatory server.

## Product Purpose

MaaS Observatory turns scheduled, real streaming requests into clear, comparable response measurements. It helps users choose a deployment and recognize changes without presenting synthetic checks as model-quality benchmarks or inferring unavailable server internals.

## Brand Personality

Precise, calm, direct. The product should feel confident and human without becoming conversational, promotional, or coldly diagnostic.

## Anti-references

Avoid debug panels, dense infrastructure consoles, neon science-fiction styling, generic AI gradients, oversized numbered sections, explanatory slogans, and unexplained protocol terminology in primary UI.

## Design Principles

- Lead with what a model user sees: current availability, first response, and
  output speed.
- A failed latest request must never be masked by an older successful value.
- Combine compact and extended inputs through one fixed, balanced sample suite.
- Keep methodology in documentation and API metadata instead of repeating it
  throughout the primary interface.
- Never display a value whose source or statistical boundary cannot be defended.
- Use familiar product interactions and consistent language.
- Keep every result traceable without exposing collection internals in the
  user-facing summary.

## Accessibility & Inclusion

Meet WCAG 2.1 AA. Support keyboard navigation, visible focus, semantic status text, sufficient contrast, screen-reader labels, and reduced-motion preferences. Never communicate state through color alone.
